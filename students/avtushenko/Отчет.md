### Часть 3. Domain Layer (Доменный слой)

#### Доменные сущности

**Entity 1**: TestResult

```python
# domain/models/test_result.py
class TestResult:
    """Доменная сущность: Результат попытки теста"""
    def __init__(self, attempt_id: str, user_id: str, course_id: str, score: float):
        self.id = attempt_id
        self.user_id = user_id
        self.course_id = course_id
        self.score = score
        self.timestamp = datetime.utcnow()
        self.passed = score >= 80.0
```

**Value Object 1**: Score

```python
# domain/models/value_objects.py
@dataclass(frozen=True)
class Score:
    value: float
    def __post_init__(self):
        if not (0 <= self.value <= 100):
            raise ValueError("Score must be between 0 and 100")
```

**Доменные исключения**:
- VideoNotCompletedError (Тест заблокирован, видео < 100%)
- MaxAttemptsReachedError (Превышен лимит в 3 попытки)
- CourseProgressNotFoundError

#### Бизнес-правила

Перечислите основные бизнес-правила, реализованные в domain слое:

1. Тест разблокируется только при video_progress == 100%
2. Максимум 3 попытки сдачи теста на один курс
3. Проходной балл: score >= 80%
4. Прогресс монотонен: не может уменьшаться при синхронизации устройств
5. Комментарий ограничивается 1000 символами

#### Исходящий адаптер: Repository

```python
# infrastructure/adapter/out/in_memory_repository.py
class InMemoryProgressRepository(IProgressRepository):
    def __init__(self): self.db = {}
    def save_progress(self, progress): self.db[f"{progress.user_id}_{progress.course_id}"] = progress
    def get_progress(self, user_id, course_id): return self.db.get(f"{user_id}_{course_id}")
```

**Принцип работы**:
Хранение в памяти (dict) для демонстрации архитектуры. В ЛР #5 будет заменён на PostgreSQL.

### Часть 6. Dependency Injection (Конфигурация зависимостей)

```python
# infrastructure/config/dependency_injection.py
class Container:
    def __init__(self):
        self.repo = InMemoryProgressRepository()
        self.notifier = ConsoleNotificationService()
        self.service = CourseProgressService(
            repository=self.repo,
            notifier=self.notifier
        )
    
    def get_service(self):
        return self.service
```

**Как работает DI**:
CourseProgressService не знает о конкретных реализациях. Зависимости передаются через конструктор. При замене InMemoryProgressRepository на PostgresProgressRepository domain и application слои изменять не нужно.

## 6. Выводы

### Что получилось хорошо

Удалось чётко изолировать доменную модель (Progress, Score, бизнес-правила) от инфраструктуры. Domain-слой не содержит импортов фреймворков, БД или HTTP. CourseProgressService легко тестируется благодаря внедрению интерфейсов портов через конструктор.

### С какими трудностями столкнулись

Первоначально было непонятно, куда выносить валидацию video_progress == 100%: в контроллер или в домен. После анализа поняли, что это бизнес-инвариант, поэтому проверка должна находиться в Application Service или самой сущности, а инфраструктура только передаёт сырые данные.

### Что узнали нового

Освоил принципы Hexagonal Architecture и Dependency Inversion. Понял, что интерфейсы портов создаются не "на будущее", а для строгого контроля зависимостей и тестируемости. Узнал, как Direction of Dependencies гарантирует, что domain никогда не знает о деталях реализации.

### Как можно улучшить

Добавить реальную PostgreSQL-реализацию репозитория, внедрить Transactional Outbox для гарантированной доставки уведомлений, покрыть тестами граничные случаи (конкурентные попытки сдачи теста, рассинхронизация прогресса).
