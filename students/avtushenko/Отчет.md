## Ход выполнения работы

### 1. Команды (Commands)

**Созданные команды:**

1. **CreateCourseCommand** - создание нового курса
   - Поля: `title`, `description`
   - Валидация: не пустые строки, длина title ≤ 200 символов
   - Файл: `application/command/create_course_command.py`

2. **EnrollStudentCommand** - запись студента на курс
   - Поля: `student_id`, `course_id`
   - Валидация: ID не пустые
   - Файл: `application/command/enroll_student_command.py`

3. **CompleteLessonCommand** - завершение урока
   - Поля: `enrollment_id`, `lesson_id`
   - Валидация: ID не пустые
   - Файл: `application/command/complete_lesson_command.py`

4. **PassTestCommand** - прохождение теста
   - Поля: `enrollment_id`, `lesson_id`, `selected_option_index`
   - Валидация: ID не пустые, index ≥ 0
   - Файл: `application/command/pass_test_command.py`

**Пример кода команды:**
```python
@dataclass(frozen=True)
class CreateCourseCommand:
    """Команда для создания нового курса"""
    title: str
    description: str
    
    def __post_init__(self):
        if not self.title or not self.title.strip():
            raise ValueError("Course title cannot be empty")
        if len(self.title) > 200:
            raise ValueError("Course title too long (max 200 chars)")
        if not self.description:
            raise ValueError("Course description cannot be empty")

### 2. Command Handlers

**Созданные обработчики:**

1. **CreateCourseHandler** - создание курса
   - Шаги: генерация ID → создание Course → сохранение → возврат ID
   - Возвращает: ID курса
   - Файл: `application/command/handlers/create_course_handler.py`

2. **EnrollStudentHandler** - запись на курс
   - Шаги: проверка курса → проверка дубликатов → создание Enrollment → сохранение → публикация событий
   - Возвращает: ID записи
   - Файл: `application/command/handlers/enroll_student_handler.py`

3. **CompleteLessonHandler** - завершение урока
   - Шаги: загрузка Enrollment → вызов complete_lesson() → сохранение → публикация событий
   - Файл: `application/command/handlers/complete_lesson_handler.py`

4. **PassTestHandler** - прохождение теста
   - Шаги: загрузка Enrollment → загрузка Lesson → проверка ответа → сохранение → публикация событий
   - Возвращает: bool (правильно/неправильно)
   - Файл: `application/command/handlers/pass_test_handler.py`

**Пример кода handler:**
```python
class EnrollStudentHandler:
    def handle(self, command: EnrollStudentCommand) -> str:
        # 1. Проверка существования курса
        course = self._course_repository.find_by_id(command.course_id)
        if not course:
            raise ValueError(f"Course {command.course_id} not found")
        
        # 2. Проверка дубликатов
        existing = self._enrollment_repository.find_by_student_and_course(
            command.student_id, command.course_id
        )
        if existing:
            raise ValueError(f"Student already enrolled")
        
        # 3. Создание агрегата
        enrollment = Enrollment(enrollment_id, command.student_id, command.course_id)
        enrollment.set_total_lessons(len(course.lesson_ids))
        
        # 4. Сохранение и публикация событий
        self._enrollment_repository.save(enrollment)
        for event in enrollment.get_events():
            self._publish_event(event)
        
        return enrollment_id
```

### 4. Query Handlers

**Созданные обработчики запросов:**

1. **GetCourseByIdHandler** - получение курса
   - Репозиторий: `course_repository`
   - Возвращает: `CourseDTO`
   - Файл: `application/query/handlers/get_course_by_id_handler.py`

2. **ListCoursesHandler** - список курсов с фильтрацией
   - Репозиторий: `course_repository`
   - Возвращает: `List[CourseDTO]`
   - Фильтрация по рейтингу, пагинация

3. **GetStudentProgressHandler** - прогресс студента
   - Репозиторий: `enrollment_repository`
   - Возвращает: `EnrollmentDTO (или пустой прогресс)`

**Пример кода:**
```python
class GetCourseByIdHandler:
    def handle(self, query: GetCourseByIdQuery) -> CourseDTO:
        course = self._course_repository.find_by_id(query.course_id)
        if not course:
            raise ValueError(f"Course {query.course_id} not found")
        
        return CourseDTO(
            id=course.id,
            title=course.title,
            description=course.description,
            rating=course.rating.value if course.rating else None,
            lesson_ids=course.lesson_ids,
            total_lessons=len(course.lesson_ids)
        )
```

### 5. Application Service (Фасад)

**Реализованный сервис:** `CourseService`

**Методы:**

| Метод | Тип | Возвращает |
|-------|-----|------------|
| `create_course(command)` | Command | ID курса |
| `enroll_student(command)` | Command | ID записи |
| `complete_lesson(command)` | Command | void |
| `pass_test(command)` | Command | bool |
| `get_course_by_id(query)` | Query | CourseDTO |
| `list_courses(query)` | Query | List[CourseDTO] |
| `get_student_progress(query)` | Query | EnrollmentDTO |

**Пример кода:**
```python
class CourseService:
    def __init__(self, repositories):
        self._create_course_handler = CreateCourseHandler(repositories["course_repository"])
        self._enroll_student_handler = EnrollStudentHandler(
            repositories["enrollment_repository"],
            repositories["course_repository"]
        )
        # ... инициализация других handlers
    
    def create_course(self, command: CreateCourseCommand) -> str:
        return self._create_course_handler.handle(command)
    
    def get_course_by_id(self, query: GetCourseByIdQuery) -> CourseDTO:
        return self._get_course_by_id_handler.handle(query)
```

## Контрольные вопросы

1. **В чём разница между Command и Query?**
   - Command изменяет состояние системы (пишущая операция), Query только читает данные без изменений. Command возвращает void или ID, Query возвращает DTO.

2. **Почему Command Handler возвращает только ID, а не весь объект?**
   - Чтобы избежать утечки доменной модели наружу. Клиент должен делать отдельный GET-запрос для получения данных, что соответствует принципу CQRS.

3. **Где должна выполняться валидация: в команде, обработчике или доменной модели?**
   - Валидация примитивов (не пусто, диапазон) - в команде/обработчике. Бизнес-инварианты - в доменной модели.

4. **Можно ли вызывать Query из Command Handler?**
   - Технически можно, но не рекомендуется (нарушает CQRS). Лучше загружать данные через Repository.

5. **Зачем разделять Request DTO (от клиента) и Command (внутренний)?**
   - Request DTO зависит от формата API (HTTP/JSON), а Command - внутренняя структура приложения. Разделение позволяет независимо менять API и бизнес-логику.

## Вывод

Реализован прикладной слой для системы мини-курсов «Учусь быстро» с разделением на команды и запросы (CQRS). Созданы 4 команды, 4 обработчика команд, 3 запроса, 3 обработчика запросов и 3 DTO. Application Service (CourseService) выступает фасадом, делегируя вызовы специализированным обработчикам. Все обработчики покрыты юнит-тестами с использованием mock-объектов. Команды иммутабельны, запросы не изменяют состояние системы. Доменные события публикуются после успешного сохранения изменений.
