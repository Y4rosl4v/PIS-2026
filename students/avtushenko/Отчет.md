## Ход выполнения работы

### 1. Протофайлы (.proto)

**Созданные протофайлы:**

| Файл | Содержимое |
|------|-----------|
| `common.proto` | Общие типы (Status, Progress, Timestamp) |
| `course_service.proto` | Сервис курсов (5 методов) |
| `enrollment_service.proto` | Сервис записей и прогресса (8 методов) |

**Схема сервисов:**

```protobuf
// Course Service (Unary + Server streaming)
service CourseService {
  rpc CreateCourse(CreateCourseRequest) returns (CreateCourseResponse);
  rpc GetCourse(GetCourseRequest) returns (Course);
  rpc ListCourses(ListCoursesRequest) returns (ListCoursesResponse);
  rpc UpdateRating(UpdateRatingRequest) returns (Course);
  rpc AddLesson(AddLessonRequest) returns (Lesson);
  rpc StreamCourseUpdates(StreamCourseRequest) returns (stream CourseUpdate);
}

// Enrollment Service (All 4 RPC patterns)
service EnrollmentService {
  // Unary RPCs
  rpc EnrollStudent(EnrollStudentRequest) returns (EnrollStudentResponse);
  rpc GetEnrollment(GetEnrollmentRequest) returns (Enrollment);
  rpc GetStudentProgress(GetStudentProgressRequest) returns (StudentProgress);
  rpc CompleteLesson(CompleteLessonRequest) returns (CompleteLessonResponse);
  rpc PassTest(PassTestRequest) returns (PassTestResponse);
  
  // Server-side streaming
  rpc StreamProgress(StreamProgressRequest) returns (stream ProgressUpdate);
  
  // Client-side streaming
  rpc BatchEnroll(stream EnrollStudentRequest) returns (BatchEnrollResponse);
  
  // Bidirectional streaming
  rpc InteractiveProgress(stream ProgressCommand) returns (stream ProgressUpdate);
}
```

### 2. gRPC Server

**Реализованные методы:**
```
Тип RPC	| Методы	| Описание
Unary	| CreateCourse, GetCourse, ListCourses, EnrollStudent, CompleteLesson	| Стандартные запрос-ответ
Server streaming	| StreamCourseUpdates, StreamProgress	| Real-time обновления
Client streaming	| BatchEnroll	| Массовая запись студентов
Bidirectional	| InteractiveProgress	| Интерактивное отслеживание
```

---

### 3. gRPC Client

**Примеры вызовов**
```python
# Unary RPC
course_client = CourseServiceClient(channel)
course_id = course_client.create_course("Python Basics", "Learn Python")

# Server-side streaming
course_client.stream_course_updates(course_id="ALL")

# Client-side streaming (batch)
enrollment_client.batch_enroll([
    ("STU001", course_id1),
    ("STU002", course_id1),
    ("STU003", course_id2)
])

# Bidirectional streaming
enrollment_client.interactive_progress("STU001", course_id1)
```

### 4. Server-Side Streaming

**Сценарий:**
Клиент подписывается на обновления курсов → сервер отправляет все изменения
```
Client                          Server
   │                               │
   ├─────── Subscribe ────────────►│
   │                               │
   │◄────── Course Created ────────┤
   │                               │
   │◄────── Rating Changed ────────┤
   │                               │
   │◄────── Student Enrolled ──────┤
   │                               │
```
---

### 5. Client-side Streaming (Batch операции)

**Сценарий:**
Массовая запись студентов одним запросом
```python
# Один вызов = 100 записей
enrollment_client.batch_enroll([(f"STU{i}", course_id) for i in range(100)])

# Результат:
Batch enrollment completed:
   Total: 100
   Succeeded: 98
   Failed: 2
   ✗ STU050 -> Already enrolled
```
---

### 6. Bidirectional Streaming (Интерактивное взаимодействие)

**Сценарий:**
Клиент отправляет команды, сервер отвечает обновлениями
```
Client                          Server
   │                               │
   ├─── Start Tracking ───────────►│
   │◄── Current Progress ──────────┤
   │                               │
   ├─── Get Status ───────────────►│
   │◄── Status Update ─────────────┤
   │                               │
   ├─── Stop Tracking ────────────►│
   │◄── Final Update ──────────────┤
```

## Контрольные вопросы

1. **В чём преимущество gRPC над REST?**
   - Производительность (Protocol Buffers бинарный), строгая типизация, автоматическая генерация клиентов, поддержка streaming (4 типа), HTTP/2 мультиплексирование.

2. **Почему Protocol Buffers быстрее JSON?**
   - Protobuf бинарный формат → меньше размер, быстрее сериализация/десериализация. JSON текстовый → больше размер, парсинг сложнее.

3. **Зачем нужен streaming в gRPC?**
   - Real-time обновления (Server streaming: подписка на события). Обработка больших данных (Client streaming: batch операции). Интерактивное взаимодействие (Bidirectional: диалоговые сценарии).
